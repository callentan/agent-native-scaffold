# REQ-NNN：待填写

> 空白表单，不是已确认需求。先读[业务需求指引](../../stakeholder-requirements/README.md#req-writing)，按需复制到 `stakeholder-requirements\REQ-NNN-<slug>.md`。复制后删除本提示，替换占位编号、标题与锚点，并核对相对链接。

<a id="basis"></a>
## 来源与状态

| 字段 | 内容 |
|---|---|
| 状态 | 草稿，待确认 |
| 提出者、来源及可定位依据 | 待填写 |
| 记录日期、确认人及确认依据 | 待填写；没有确认不得写已批准 |
| 所属产品目标、用户或干系人 | 待填写：引用产品说明，不另写一份 PRD |
| 领域概念、上下文与规则 | 待填写：实际 ID 及稳定相对链接；不适用需说明 |

<a id="business-need"></a>
## 业务需要与范围

- 一项业务需要及理由：待填写。
- 适用对象、前提与范围：待填写。
- 非目标与约束来源：待填写。
- 未决事实及对本需求的影响：待填写。

规则正文留在领域模型；这里引用规则并说明业务需要，不重复维护规则数值或全文。

<a id="acceptance"></a>
## 业务验收

逐项复制以下块，使用带所属 REQ 的唯一 ID 和固定 ASCII 锚点，不能只有 `AC-01`。所有内容待填写，ID 示意不是正式验收。

<a id="req-nnn-ac-01"></a>
### REQ-NNN-AC-01：待填写

| 项目 | 内容 |
|---|---|
| 业务前提与场景范围 | 待填写 |
| 业务动作或触发 | 待填写 |
| 可观察的业务结果与判定标准 | 待填写 |
| 边界、例外或禁止的结果 | 待填写；未定义部分保持未决 |
| 相关规则/上下文及确认来源 | 待填写：ID、稳定链接与依据 |

此处不记录执行结果。VT 保存其业务验收目标，按完整 ID 反向查找；缺少 VT 或未执行都不是通过，软件检查通过也不自动证明本项成立。
