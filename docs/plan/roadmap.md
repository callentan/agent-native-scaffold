# Repo 模板首版实施与验收

**这是按 2026-10-13 模板方向重写的计划，尚未实施。此前的 CLI、协调器、状态库和平台适配开发里程碑不再沿用，旧工期估计也不适用于本计划。**

## 1. 首版交付目标

交付一套可复制的研发 repo 模板，包含项目资料模板和 Agent 能力文件。用户完成必要的项目设置后，可以使用 GitHub Copilot 开始工作；其他能读写仓库的 Agent 有明确的通用接入路径。

目录命名采用 DDD 与参考工程的例子：`domain-model`、`stakeholder-requirements`、`software-requirements`、`user-stories`、`architecture`、`verification`，表单集中在 `_templates`。这是命名和资料分工的选择，不是继承完整方法、参考源码或多仓库依赖。

验收重点是“拿到项目就能找到资料、开始任务、验证变更并留下可接手记录”，而不是执行器能否无人值守运行。模板不需要额外的 skeleton 软件包、服务、个人 skills 或参考仓库权限。

| 首版包含 | 不包含 |
|---|---|
| README、AGENTS、领域/REQ/SR/US/ABB/VT/日志/ADR 的填写指引与表单 | 自研 CLI、生成器、执行循环、状态数据库 |
| Copilot 仓库级和按路径 instructions | 自建审批系统、可信发布器、权限隔离层 |
| 少量实用 custom agents、skills 和 prompt files | 自动编排的角色团队、任务队列或 Web 平台 |
| 真实的模板使用说明、交接约定和兼容记录 | 所有客户端原生功能完全一致的承诺 |
| 一个自有最小项目上的使用演练 | 强制完整 DDD、监管流程、旧项目迁移或指定业务技术栈 |
| 模板来源版本、更新说明、正常 diff 合入 | 自动覆盖式升级和跨仓库同步 |

技术栈无关的模板应能直接用于需求、规划和记录。编码、构建与测试演练使用一个明确选定的自有小项目，不等于模板内置所有语言的可运行应用。

## 2. 实施顺序

| 阶段 | 交付内容 | 前置条件 |
|---|---|---|
| P0：确定最小内容 | 细化已选参考命名下的文件职责、Copilot 首测使用界面及一个合成样例任务 | 模板形态与参考命名方向已确认；具体内容设计评审 |
| P1：项目资料模板 | 按 DDD 参考目录组织入口和说明，集中编写 `_templates` 表单与设置指引 | P0 |
| P2：Agent 能力文件 | Copilot instructions、少量 agents、skills、prompts；共用模板和流程 | P1 的目录与文件职责明确 |
| P3：实际使用与发布准备 | 冷启动、开发、交接、兼容演练；修订文件；整理可分发内容 | P1、P2，以及演练客户端和项目环境可用 |

不为每个文件建立独立发布包。先用一套可审阅的内容完成一次真实工作，再根据使用问题补充规则。

## 3. 阶段退出条件

### P0：范围足够小且具体

- 区分正式模板与本仓库研究资料，确认发布前的材料处理边界。
- 确定首批有用的文档、skills 和 prompts；不因“可能以后用到”扩充目录。
- 标明哪些路径沿用参考记录、哪些是单仓整理或自有补充；命名依据见蓝图，不假称整棵目录树来自某一个 repo。
- 明确 Copilot 首测使用界面；建议先用 VS Code agent mode，其余使用界面分别记录，不默认混为一种支持。
- 选定自有合成任务和演练所需的技术栈；不将参考项目当默认试点。
- 明确首次设置需要用户提供什么，哪些字段可以留为未决，哪些必须在编码前确认。

### P1：资料模板能被直接使用

- README 清楚区分首次设置、日常开发与接手任务。
- REQ、SR、US、ABB、VT 和日志的职责无重复；表单与正式工件分开，填写提示不被误认成已确认事实。
- PRD 的产品说明和功能规格有明确落点，不再并存一组同内容的泛化目录；维护任务无需硬套 User Story。
- 验证文档与实际测试代码分开，开发日志只引用结果，不维护另一份验收事实。
- 未选技术栈时不提供假构建和假测试成功；选定后记录真实命令与工作目录。
- 通用入口可定位目标、规范、任务、开发命令和相关日志。
- 不需要额外的 manifest、状态文件或全局工具安装才能阅读和开始使用。

### P2：能力文件连接起来

- Copilot 原生文件的目录、命名和必要元数据符合目标客户端约定。
- Custom agent 只定义工作模式；skill 保留方法正文；prompt 负责本次输入，不复制三份流程。
- Skill 引用 `_templates` 中的表单并写明正式产物目录，不依赖作者的本地路径、个人 skills 或隐藏聊天记忆。
- 通用入口说明如何显式读取 skill 和专项规则，未自动发现时有可操作的接入方法。
- 不支持 prompt files 的客户端能用自然语言完成同一任务，不要求专属快捷命令。
- 受限工具配置需要实际验证；未验证时不宣传为安全边界。

### P3：演练通过后再发布

- 在干净的下游项目中，从设置到一个小功能或缺陷修复，真实走完开发、验证与记录。
- 新会话仅凭仓库、必要的外部授权和当前任务接手，不依赖旧对话。
- 完成 Copilot 首测使用界面的检查；其他客户端明确列为已测、仅有文档依据或未测试。
- 以另一个客户端或显式文件读取方式演练通用接入；不能据此扩大为“全部 Agent 已验证”。
- 核对下游内容没有内部研究材料、个人绝对路径、密钥或假业务事实。
- 发布说明包含模板版本、适用范围、必要设置和限制；仓库模板标记、权限及可见性由维护者另行确认。

## 4. 首批验收场景

以下是模板实现后的验收清单，不是本次已经通过的测试结果。

| ID | 场景 | 可观察的通过条件 |
|---|---|---|
| T01 | 复制模板并首次打开 | 不安装自研工具；README 能指引完成必要设置，未决项被明确记录 |
| T02 | Copilot 冷启动 | 实际读取入口和相关资料，能正确指出目标、规范、任务、命令与日志位置 |
| T03 | 原生能力入口 | 目标界面能发现所声明的 agents/skills/prompts；仅检查文件存在不算通过 |
| T04 | 不依赖 prompt 快捷入口 | 使用自然语言和显式文件读取，完成相同的工作步骤 |
| T05 | 小功能或缺陷修复 | 依据相关 SR/US 或缺陷记录修改已有代码，执行项目真实检查，留下结果与限制 |
| T06 | 换会话接手 | 根据任务、日志和 Git 状态继续；发现过期记录时先核验，不盲目复用结果 |
| T07 | 缺需求或验证不可用 | 明确提出问题或标记未验证，不编造需求、测试成功或批准 |
| T08 | 已有项目合入 | 原配置、文档与用户改动保留；冲突被明确报告，不重新覆盖整个工程 |
| T09 | 无参考项目访问权 | 完成设置与开发演练，不读取参考源码或依赖参考项目凭据 |
| T10 | 权限和发布限制 | 无授权不推送或改变保护设置；复制模板不被报告为已启用审批、隔离或 CI |
| T11 | 目录与工件归属 | 入口、表单和 skills 指向同一套参考命名；可区分 SR、US、验证文档、测试代码与开发日志，不重复创建同内容的需求或任务 |

记录使用界面、版本、实际读取的文件、执行结果和人工修正。失败就修订模板，不把 Agent 的“已完成”作为唯一判据；未运行的场景明确保留为未验证。

模板检查与模型行为演练是两件事：相对链接、元数据和文件格式可用现有工具检查；是否正确读取资料、处理缺失输入和完成任务，需要实际会话。有限演练不构成安全证明或成功率承诺。

## 5. 后续按实际需要扩展

更多 Agent 的薄入口、技术栈专项规则、接口/数据/运维文档模板，以及更深的 DDD 建模内容，都以真实使用需求为前提。已有目录命名不要求填满全部领域工件，也不要为兼容性预先复制多套正文。

项目需要 CI、开发容器或检查脚本时，复用该技术栈与平台的原生机制。不把这些需求重新扩展成 skeleton 运行时、自动发布引擎或跨项目管理平台。
