# Local development deployment

Run a private Flagsmith instance on one developer workstation with Docker Compose. This setup is for feature-flag integration, manual testing, and POCs, not production HA. It does not use the production [Helm values](helm/values.common.yaml), create cloud resources, or deploy a business application.

The examples target **Windows with PowerShell 7.4 or newer and Docker Desktop running Linux containers**. They use the official unified Flagsmith image, which serves the Dashboard and REST API together. No separate OpenFeature server, Redis, Kubernetes cluster, or external PostgreSQL installation is required.

This document provides configuration and script examples to save locally. They are not separate checked-in deployment files. Complete the first-install Console configuration below as well as the container checks: an HTTP 200 response for the Dashboard's HTML does not prove that its JavaScript application can initialize.

To switch this installation to a licensed Enterprise image, follow [Enterprise activation](enterprise-activation.md). That process preserves the database and requires vendor-provided image access, a licence, and its signature.

## 1. Topology and prerequisites

| Service | Image / command | Purpose and access |
| --- | --- | --- |
| `postgres` | `postgres:15-alpine` | Local database and task storage; named volume; no host port |
| `migrate-db` | `docker.flagsmith.com/flagsmith/flagsmith:2.285.0`, `migrate` | One-shot schema migration after PostgreSQL is healthy |
| `flagsmith` | Same Flagsmith image, `serve` | Dashboard and API at `http://localhost:8000`, published only on `127.0.0.1` |
| `flagsmith-task-processor` | Same Flagsmith image, `run-task-processor` | Asynchronous tasks; no host port |

Startup order is PostgreSQL readiness, successful migration, then the API and worker. A migration container exiting with code `0` is expected; it should not remain running.

Prepare:

- Docker Desktop, its Linux container backend, and Docker Compose v2.20 or newer. Use the Compose v2 plugin (`docker compose`), not legacy `docker-compose`.
- PowerShell 7.4 or newer, available as `pwsh.exe`.
- Access to `docker.flagsmith.com` and Docker Hub, or approved internal mirrors. Configure corporate proxy and CA trust through the normal Docker process; do not disable certificate validation.
- An unused local TCP port `8000`. Start with about 4 GB of memory available to Docker and sufficient disk space for images and database growth; this is a workstation allowance, not a measured minimum.

Flagsmith is pinned to `2.285.0` to match this repository's reference version. The PostgreSQL tag follows the current patch of major version 15; it is not an immutable image lock. Record approved digests if exact reproduction is required. Do not change the PostgreSQL major version against an existing volume without a supported database upgrade.

Keep this environment separate from shared development and production: use only synthetic test users, traits, flags, and credentials.

## 2. Save the local configuration

Create `%LOCALAPPDATA%\FlagsmithDev` in File Explorer. The usual expanded path is `C:\Users\<user>\AppData\Local\FlagsmithDev`. Save the two examples below in that directory, **outside the repository**:

| File | Contents |
| --- | --- |
| `compose.yaml` | Compose configuration below |
| `Invoke-LocalFlagsmith.ps1` | PowerShell 7 helper below |
| `.env` | Generated by the helper's `Init` action; do not create it with shared default passwords |
| `compose.mirror.json` | Optional, generated by `ConfigureMirror`; selects the domestic image source for all services without changing Docker globally |
| `compose.runtime.json` | Local Console environment override, added during first-install configuration below |

Keep the directory private to your Windows account. The `.env` file is plaintext local secret storage, not a vault. Do not commit it, share it, or attach it or rendered Compose configuration to a support ticket.

### compose.yaml

```yaml
x-flagsmith-env: &flagsmith-env
  DATABASE_URL: "postgresql://flagsmith:${POSTGRES_PASSWORD:?Run Init first}@postgres:5432/flagsmith"
  DJANGO_SECRET_KEY: "${DJANGO_SECRET_KEY:?Run Init first}"
  ENVIRONMENT: local
  DJANGO_ALLOWED_HOSTS: "localhost,127.0.0.1,flagsmith"
  DJANGO_CSRF_TRUSTED_ORIGINS: "http://localhost:8000"
  FLAGSMITH_DOMAIN: "localhost:8000"
  API_URL: "http://localhost:8000/api/v1/"
  USE_SECURE_COOKIES: "false"
  COOKIE_SAME_SITE: Lax
  CORS_ORIGIN_ALLOW_ALL: "false"
  CORS_ALLOWED_ORIGINS: "http://localhost:4200"
  TASK_RUN_METHOD: TASK_PROCESSOR
  USE_POSTGRES_FOR_ANALYTICS: "true"
  ENABLE_TELEMETRY: "false"
  EMAIL_BACKEND: django.core.mail.backends.console.EmailBackend
  PREVENT_SIGNUP: "false"
  ALLOW_REGISTRATION_WITHOUT_INVITE: "true"
  ENABLE_EMAIL_ACTIVATION: "false"
  FLAGSMITH_ON_FLAGSMITH_API_URL: "http://localhost:8000/api/v1/"

services:
  postgres:
    image: postgres:15-alpine
    environment:
      POSTGRES_USER: flagsmith
      POSTGRES_PASSWORD: "${POSTGRES_PASSWORD:?Run Init first}"
      POSTGRES_DB: flagsmith
    volumes:
      - pgdata:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD", "pg_isready", "-U", "flagsmith", "-d", "flagsmith"]
      interval: 2s
      timeout: 3s
      retries: 30
      start_period: 20s

  migrate-db:
    image: docker.flagsmith.com/flagsmith/flagsmith:2.285.0
    command: ["migrate"]
    environment: *flagsmith-env
    healthcheck:
      disable: true
    depends_on:
      postgres:
        condition: service_healthy

  flagsmith:
    image: docker.flagsmith.com/flagsmith/flagsmith:2.285.0
    command: ["serve"]
    environment: *flagsmith-env
    ports:
      - "127.0.0.1:8000:8000"
    depends_on:
      migrate-db:
        condition: service_completed_successfully

  flagsmith-task-processor:
    image: docker.flagsmith.com/flagsmith/flagsmith:2.285.0
    command: ["run-task-processor"]
    environment: *flagsmith-env
    depends_on:
      migrate-db:
        condition: service_completed_successfully

volumes:
  pgdata:
```

The `DATABASE_URL` uses Compose service DNS (`postgres`), not `localhost`. Generated passwords contain only hexadecimal characters, so they are safe in this URL without further encoding. If supplying a different password, URL-encode it in `DATABASE_URL` without changing the actual PostgreSQL password.

For the **unified image**, the Dashboard API override is `API_URL`, as used above. Do not copy the standalone frontend image's configuration without checking how that image reads its environment. Local HTTP requires non-secure cookies and `SameSite=Lax`; these are local-only settings. The only permitted cross-origin browser origin here is `http://localhost:4200`. CORS does not provide authentication or authorization.

### Invoke-LocalFlagsmith.ps1

This PowerShell 7 script explicitly anchors its working directory and Compose paths to its own directory. It preserves existing secrets, checks external exit codes, and never removes data unless `Reset` and its confirmation switch are both supplied. `ConfigureMirror` writes only a local Compose override; it does not edit Docker Desktop settings, configure insecure registries, or restart Docker.

```powershell
[CmdletBinding()]
param(
    [Parameter(Mandatory)]
    [ValidateSet('Init', 'ConfigureMirror', 'Check', 'Pull', 'Start', 'Status', 'Logs', 'Stop', 'Reset')]
    [string]$Action,
    [switch]$ConfirmDataLoss
)

Set-StrictMode -Version Latest
$ErrorActionPreference = 'Stop'
$root = $PSScriptRoot
Set-Location -LiteralPath $root
$composeFile = Join-Path $root 'compose.yaml'
$envFile = Join-Path $root '.env'
$mirrorFile = Join-Path $root 'compose.mirror.json'
$runtimeFile = Join-Path $root 'compose.runtime.json'

if (-not (Test-Path -LiteralPath $composeFile -PathType Leaf)) {
    throw "Save compose.yaml first: $composeFile"
}

if ($Action -eq 'Init') {
    if (Test-Path -LiteralPath $envFile) {
        throw "Refusing to replace existing secrets: $envFile"
    }
    $password = [Convert]::ToHexString(
        [System.Security.Cryptography.RandomNumberGenerator]::GetBytes(24))
    $djangoKey = [Convert]::ToHexString(
        [System.Security.Cryptography.RandomNumberGenerator]::GetBytes(48))
    $content = "POSTGRES_PASSWORD=$password`nDJANGO_SECRET_KEY=$djangoKey`n"
    $stream = [System.IO.File]::Open(
        $envFile, [System.IO.FileMode]::CreateNew, [System.IO.FileAccess]::Write)
    try {
        $bytes = [System.Text.Encoding]::UTF8.GetBytes($content)
        $stream.Write($bytes, 0, $bytes.Length)
    } finally {
        $stream.Dispose()
    }
    Write-Output "Created local secrets: $envFile"
    exit 0
}

if (-not (Test-Path -LiteralPath $envFile -PathType Leaf)) {
    throw 'Run the Init action first.'
}
if ($Action -eq 'Reset' -and -not $ConfirmDataLoss) {
    throw 'Reset deletes all local Flagsmith data. Add -ConfirmDataLoss only when intended.'
}

if ($Action -eq 'ConfigureMirror') {
    $flagsmithImage = 'docker.1ms.run/flagsmith/flagsmith:2.285.0'
    $override = @{
        services = @{
            postgres = @{ image = 'docker.1ms.run/library/postgres:15-alpine' }
            'migrate-db' = @{ image = $flagsmithImage }
            flagsmith = @{ image = $flagsmithImage }
            'flagsmith-task-processor' = @{ image = $flagsmithImage }
        }
    }
    $override | ConvertTo-Json -Depth 4 |
        Set-Content -LiteralPath $mirrorFile -Encoding utf8
    Write-Output "Saved per-project image mirror configuration: $mirrorFile"
    Write-Output 'Run Check, then Pull. Configuration alone does not prove downloads work.'
    exit 0
}

$docker = (Get-Command -Name docker.exe -CommandType Application).Source
[string[]]$arguments = @(
    'compose', '--project-name', 'flagsmith-local',
    '--project-directory', $root, '--env-file', $envFile, '--file', $composeFile
)
if (Test-Path -LiteralPath $mirrorFile -PathType Leaf) {
    $arguments += @('--file', $mirrorFile)
}
if (Test-Path -LiteralPath $runtimeFile -PathType Leaf) {
    $arguments += @('--file', $runtimeFile)
}
[string[]]$operation = switch ($Action) {
    'Check'  { 'config'; '--quiet' }
    'Pull'   { 'pull' }
    'Start'  { 'up'; '--detach'; '--wait'; '--wait-timeout'; '180' }
    'Status' { 'ps'; '--all' }
    'Logs'   { 'logs'; '--tail'; '100' }
    'Stop'   { 'down' }
    'Reset'  { 'down'; '--volumes' }
}
$arguments += $operation
& $docker @arguments
if ($LASTEXITCODE -ne 0) { exit $LASTEXITCODE }
exit 0
```

## 3. Initialize and start

Run the following **one action at a time** from PowerShell 7. The helper sets an explicit working directory, so the caller does not need to be in the checkout or local environment directory.

Generate persistent local secrets once:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Init
```

### Configure the domestic image source

`ConfigureMirror` selects the open-source images only. Do not run it after configuring Enterprise images: it would replace their references with the public open-source images. See [Enterprise activation](enterprise-activation.md).

For a network that cannot reliably reach Docker Hub or `docker.flagsmith.com`, run:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action ConfigureMirror
```

This selects [Millisecond Mirror](https://1ms.run/) (`docker.1ms.run`) through explicit image references:

| Original image | Per-project mirror image |
| --- | --- |
| `postgres:15-alpine` | `docker.1ms.run/library/postgres:15-alpine` |
| `docker.flagsmith.com/flagsmith/flagsmith:2.285.0` | `docker.1ms.run/flagsmith/flagsmith:2.285.0` |

The second mapping uses the Flagsmith Docker Hub namespace through the mirror. It is applied to the migration, API, and worker together; do not change just the API image.

The helper saves these references in `compose.mirror.json` and automatically includes that file for every subsequent Compose action. The base YAML, `.env`, database volume, and project name stay unchanged. Rerunning `ConfigureMirror` rewrites only this generated override. To return to the original registries, remove only `compose.mirror.json` in File Explorer, then run `Check` and `Pull` again.

No Docker Desktop **Settings > Docker Engine** edit or restart is needed. Docker's `registry-mirrors` setting accelerates Docker Hub, not arbitrary registries such as `docker.flagsmith.com`; adding a Hub accelerator alone would leave that original Flagsmith address unchanged. Explicit per-project references avoid that gap and do not affect other projects.

This is a third-party public mirror, not a Flagsmith-operated or Docker-operated service. Use it only where enterprise policy permits, do not send private images or registry credentials to it, and retain normal TLS verification. Use an approved internal registry instead if public mirrors are prohibited.

### Check and pull

Validate the configuration without printing expanded credentials:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Check
```

Pull the images through the selected source. This is the download check: the action succeeds only when Compose completes all image pulls. An accessible mirror homepage or manifest does not prove image-layer downloads work. Failures retain the Docker error and nonzero exit code; the helper does not silently fall back to another mirror or change tags.

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Pull
```

On **2026-10-16**, both images were fully pulled successfully through `docker.1ms.run` on this workstation's Docker Desktop Linux engine, including their image layers:

| Image tag | Digest returned by the successful pull |
| --- | --- |
| `library/postgres:15-alpine` | `sha256:f7d23353e1b15400d22ebe31189f4d314b87a4c129cc400c8c2d8d4ca127bf81` |
| `flagsmith/flagsmith:2.285.0` | `sha256:fb2a48d5e903751bb3e50a7b353c4fc23a8abc3b25f883ec873342c495ec96f0` |

These digests record the downloaded content, not vendor signature verification or permanent mirror availability. Recheck `Pull` on your network; the PostgreSQL patch tag can change. The checks did not start containers or modify global Docker settings.

DaoCloud was also checked: both manifests were reachable, but the PostgreSQL layer download redirected to an inaccessible Docker CDN and failed. The NJU endpoint returned HTTP 403. Neither is listed here as a working fallback for this network. [DaoCloud's published restrictions](https://github.com/DaoCloud/public-image-mirror/issues/2328) include mainland-only acceleration, allowlists, and rate limits.

### Start and initialize the Dashboard

Start the stack and wait for container readiness:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Start
```

Inspect all containers, including the migration container:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Status
```

Expected state: PostgreSQL is healthy, migration has exited with code `0`, and the API and worker are running and healthy according to their image probes. A container probe is not proof that flag evaluation or task processing works; complete the checks below. If startup times out, inspect logs rather than repeatedly resetting the database.

### First-install Console configuration

Flagsmith uses feature flags to configure its own Dashboard. In this release, the frontend ships with a default SaaS environment key. Pointing `FLAGSMITH_ON_FLAGSMITH_API_URL` at a new local database without providing a matching local key makes `/api/v1/flags/` return HTTP 403, and the Dashboard renders a Maintenance page even though container and API health checks pass.

Initialize a separate local Console environment before using normal Dashboard signup:

1. On a fresh database, open the official setup form at `http://localhost:8000/api/v1/users/config/init/` and create a superuser with a unique local password.
2. Use Django administration at `http://localhost:8000/admin/`, or an approved provisioning procedure, to create a dedicated organization, project, and environment for the self-hosted Console. Give the administrator membership in that organization. Keep this configuration project separate from business flags.
3. Copy that environment's **client-side** key into `compose.runtime.json` in the same local directory:

```json
{
  "services": {
    "flagsmith": {
      "environment": {
        "FLAGSMITH_ON_FLAGSMITH_API_KEY": "<local Console client-side environment key>"
      }
    }
  }
}
```

Replace the placeholder before continuing. This key must belong to the local Console environment, not the default cloud project or a business environment. Do not put a server-side key or management token in this file. An empty local Console environment can use the frontend's built-in feature defaults; create overrides only when needed.

Run `Start` again to apply the runtime override, then open `http://localhost:8000/login`. Confirm the sign-in form renders and the Console's `/api/v1/flags/` request succeeds. After login, create a business organization, project, and `Development` environment for application integration if they have not already been provisioned. `/signup` remains available for additional local accounts.

The Dashboard is the normal flag-management interface. `/admin/` is Django administration, not the Dashboard, and requires a superuser.

Email is written to container logs instead of sent to SMTP. This lets developers inspect local invitations and reset messages without mail infrastructure. Logs can contain sensitive links, so do not share them unredacted. Signup is intentionally enabled only for this loopback-only environment.

For the workstation installation initialized with an automatically generated administrator password, the credentials are stored in `%LOCALAPPDATA%\FlagsmithDev\admin-credentials.json`, with access restricted to the current Windows account. Open that file locally to retrieve the password, change it after first login, and never commit or share it. This is an installation-specific credential, not a shared default password.

## 4. Connect local applications

| Caller | Flagsmith base URL | Notes |
| --- | --- | --- |
| Windows-hosted .NET service / BFF | `http://localhost:8000/api/v1/` | Use a key from this local environment |
| Service attached to the same Compose network | `http://flagsmith:8000/api/v1/` | Explicitly join `flagsmith-local_default`; another Compose project does not join it automatically |
| Angular browser, optional direct SDK route | `http://localhost:8000/api/v1/` | Client-side environment key only; the example allows origin `http://localhost:4200` |
| Angular browser, recommended BFF route | Your business BFF's URL | No Flagsmith key or rules in the browser; retain existing authentication and Angular dev-proxy configuration |

`localhost` inside a business container refers to that container, not Windows or the Flagsmith container. Prefer the shared-network address above. Docker Desktop provides `host.docker.internal` for host access, but do not assume it can reach a loopback-only port on every host setup or broaden the bind address just to make it work.

For the [.NET reference](../.github/skills/openfeature-flagsmith-dotnet/references/dotnet.md), the relevant application configuration names are `FeatureFlags:ApiUrl` and `FeatureFlags:EnvironmentKey`, or environment variables `FeatureFlags__ApiUrl` and `FeatureFlags__EnvironmentKey`. Supply keys through the application's existing development-secret mechanism. Local evaluation requires a server-side `ser.` key and retrieves `/api/v1/environment-document/`; remote evaluation uses the appropriate client-side environment key.

**The checked-in .NET reference rejects HTTP URLs.** The address table describes network reachability, not an instruction to bypass that guard. To reuse that reference unchanged, place a trusted local HTTPS reverse proxy in front of Flagsmith and use its HTTPS URL. Alternatively, the target application can explicitly implement a Development-only HTTP exception restricted to approved local destinations; never disable HTTPS checks globally. Neither a proxy nor that application change is delivered by this guide.

The checked-in [.NET harness](../.github/skills/openfeature-flagsmith-dotnet/examples/dotnet) uses a synthetic transport, and the [Angular example](../.github/skills/openfeature-flagsmith-dotnet/examples/angular) contains a service and tests, not a complete application or BFF. Their existing tests do not connect to this Compose stack. Follow the [.NET](../.github/skills/openfeature-flagsmith-dotnet/references/dotnet.md) and [Angular](../.github/skills/openfeature-flagsmith-dotnet/references/frontend.md) references when integrating a real application.

Use only local environment keys. Never put a server-side key, management token, database password, or raw environment document in Angular configuration, browser storage, or source control.

## 5. Smoke checks

Create the Boolean feature `checkout_v2` in the local `Development` environment, initially disabled. In a local HTTP client such as Postman, select that environment's client-side key and send the following request; keep it in private local client settings rather than a shared collection:

| Request | Header | Expected result |
| --- | --- | --- |
| `GET http://localhost:8000/api/v1/flags/` | `X-Environment-Key: <local client-side key>` | HTTP 200; an array containing `feature.name = checkout_v2` and `enabled = false` |
| Repeat after enabling the feature | Same header | The same feature has `enabled = true`; use `enabled`, not an unrelated configuration value |
| Repeat with an invalid key | Invalid `X-Environment-Key` | A non-success authentication/authorization response, not a successful empty result |

Then check the actual application path:

1. Toggle `checkout_v2` and verify the .NET service / BFF and Angular UI after their configured refresh intervals. Server local evaluation polls rules; it is not an instant push.
2. Exercise a background action such as a local invitation. Inspect API and worker logs for the queued action and console email output. Worker readiness alone does not prove task completion.
3. Stop and start the stack using the actions below. Confirm that your account, environment, and feature value remain; do not rerun `Init`.
4. Inspect the Dashboard's browser Network panel. Its API and Console feature-configuration requests must succeed against the local instance, without HTTP 403 or unintended SaaS requests. Recheck the local key in `compose.runtime.json` against the official [Flagsmith on Flagsmith guide](https://docs.flagsmith.com/deployment-self-hosting/core-configuration/running-flagsmith-on-flagsmith) if necessary. Check egress separately; setting an API URL alone is not offline acceptance.

## 6. Logs, persistence, and reset

Read the last 100 log lines without starting a long-running watcher:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Logs
```

Stop and remove this project's containers and network while retaining the database volume:

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Stop
```

Run `Start` again to resume. Keep the `.env` file: changing `POSTGRES_PASSWORD` does not change the password inside an initialized PostgreSQL volume, and changing `DJANGO_SECRET_KEY` can invalidate signed data. A named volume persists across container recreation, but it is not a backup and may be lost when Docker Desktop storage is reset.

**Destructive reset:** the following command deletes `flagsmith-local`'s database volume, including all accounts, keys, environments, flags, and tasks. Use it only for a disposable local environment. It leaves the local configuration and `.env` file in place. Never replace it with a machine-wide Docker prune command.

```powershell
pwsh.exe -NoLogo -NoProfile -NonInteractive -File "$env:LOCALAPPDATA\FlagsmithDev\Invoke-LocalFlagsmith.ps1" -Action Reset -ConfirmDataLoss
```

Run `Start` and repeat first-install Console configuration after a reset. The old Console key in `compose.runtime.json` is no longer valid against the empty database and must be replaced. A saved administrator credentials file does not recreate the deleted account. Do not treat an application image downgrade as a database rollback; keep a database backup before testing migrations against data you need.

## 7. Troubleshooting

| Symptom | Check and corrective action |
| --- | --- |
| Docker executable, daemon, or Compose unavailable | Start Docker Desktop in Linux-container mode; verify installation and Compose version. `Check` validates configuration but does not prove daemon readiness |
| Image pull fails | For open-source images only, run `ConfigureMirror`, `Check`, and `Pull` in that order. If already configured, inspect the failing registry or blob host, proxy, CA trust, HTTP 403 / 429, and mirror policy; do not disable TLS validation. For Enterprise images, follow the private-registry checks in [Enterprise activation](enterprise-activation.md) instead |
| Pull still uses the original Flagsmith registry | Update both locally saved examples from this guide, rerun `ConfigureMirror`, and use the helper rather than a separate Compose invocation that omits the override |
| Port 8000 is in use | Stop only the known conflicting service, or change the published host port and every host/browser URL, domain, and CSRF origin in this guide; container port stays 8000 |
| PostgreSQL authentication fails after editing `.env` | Restore the original credentials or perform an authorized database password change. Do not reset a volume that contains needed data |
| `migrate-db` fails | Inspect migration and database logs. Fix the cause before starting API / worker; do not remove the dependency condition to bypass failure |
| HTTP 400 / invalid Host | Use `localhost` consistently or add the intended local hostname to `DJANGO_ALLOWED_HOSTS`. Do not set `*` as a general fix |
| Dashboard shows Maintenance while API health is good | Check the Console's `/api/v1/flags/` request. HTTP 403 after pointing the Console at the local API means its environment key is missing or belongs to another instance; finish first-install Console configuration and rerun `Start` |
| Dashboard login does not persist | Check `USE_SECURE_COOKIES=false`, `COOKIE_SAME_SITE=Lax`, and consistent `localhost` usage; clear stale cookies for this local instance |
| Browser CORS or mixed-content error | Use the BFF/dev-proxy route, or explicitly add the exact approved development origin. An HTTPS page cannot freely call an HTTP API; use local HTTPS rather than disabling browser security |
| API is healthy but background actions do not complete | Check `flagsmith-task-processor` logs, database access, and the shared `TASK_RUN_METHOD=TASK_PROCESSOR` setting |
| Flags do not change immediately | Check the selected environment/key, SDK polling, BFF snapshot TTL, and browser refresh behavior |
